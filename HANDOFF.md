## 1. What this project is (30-second version)

Revised experiments for the paper *"An Ablation Study of Hybrid Strategies for Minority-Class
Misclassification"* (rejected at ICoDT2; reviewer comments are answered point by point in
`docs/REVISED_DESIGN.md` §1).

- A full 2x2x2 factorial of three corrections, plus one extra arm, gives 9 configurations:
  **A** = SMOTETomek resampling, **B** = class weights, **C** = decision-threshold tuning,
  plus `c8` = resampling with weights recomputed after resampling.
- 7 classifiers: LR, LinearSVM, GNB, DT, RF, XGB and LGBM.
- Evaluation: nested, leakage-free 5x2 repeated stratified CV, with a 20-candidate random search
  inside every outer training fold.
- Extra experiments:
  - **E2:** a weight-sensitivity grid.
  - **E3:** a controlled imbalance sweep, only on CIC-IDS2017.
- 5 datasets: Oil Spill, SMS Spam and CIC-IDS2017 (member 1), and Pima and Credit Card Fraud
  (member 2, the owner of this machine).

All protocol code is in `common/`. Every notebook is a thin wrapper generated by
`scripts/make_notebooks.py`. Results are one CSV per experiment:
`<dataset>/<experiment>/results/<dataset>__<experiment>.csv`, with one row per
classifier × outer fold (schema in `common/io.py`).

```
python scripts/run_experiments.py --dataset cicids2017 --only e2 e3 --compile
```

- It resumes E2 at 1300/1560 (remaining: XGB folds), then runs E3 (5 imbalance levels × 9
  configs × LR/RF/XGB × 10 folds), then rebuilds `analysis/RESULTS.md`, which then gains the E2
  curves for CIC and section 9 (E3).
- Estimated time on the old laptop (5 workers): E2 about 1 h left, E3 about 2 h. Faster on a
  bigger machine.
- Set the worker count with the `N_JOBS` environment variable. It never changes results, only
  speed and memory. **Rule of thumb: about 1 GB of free RAM per worker for CIC-IDS2017.**
  E2 runs its 52 weight settings in parallel with `N_JOBS` workers, and each worker holds a
  resampled copy of the training fold.
  - Windows PowerShell: `$env:N_JOBS = "12"`
  - Linux/macOS: `export N_JOBS=12`
- If a run fails, the script retries 3 times, prints the error, and reports anything
  incomplete at the end. Rerun the same command to continue. Look at the failing notebook's
  saved outputs for the traceback.

## 6. Rules that keep results valid (important)

1. **Never edit `common/`, `requirements.txt` or `scripts/make_notebooks.py` while anything is
   running,** and always commit before starting a run. Every result row stores the git commit
   of the code (`git_commit` column). Uncommitted changes in `common/` stamp rows as
   `<sha>+dirty`, and those rows should then be deleted and recomputed.
2. **Do not change the protocol:** seeds, folds, search spaces, classifiers or the E2 grid.
   The finished datasets used them. `data/splits/*.npz` must never change after a dataset's
   first run.
3. **Never hand-edit generated experiment notebooks.** Regenerate them with
   `scripts/make_notebooks.py`. Preprocessing notebooks are the exception: they are hand-written.
4. **Keep `RESULTS_ROOT` unset** on a local machine, so results are written into the
   repository. It is only used on Colab, where results go to Google Drive.
5. `SMOKE=1` gives quick test runs that write `*__SMOKE.csv` files. These are gitignored and
   excluded from analysis. Never use them for the paper.
6. Don't run two experiments of the **same dataset/experiment** at the same time: both would
   append the same rows. Different datasets or experiments in parallel are fine. They share
   CPU and RAM, so divide `N_JOBS`.
7. Before a pull request or push: `python -m pytest tests`, then
   `python scripts/run_experiments.py --status`. Every experiment you ran must show `done`.

## 7. Decisions already made: do not "fix" these

- **CIC-IDS2017 main sample is 2% attacks** (49,000 BENIGN + 1,000 attacks, stratified by
  attack type). The natural 16.9% attack share was only mildly imbalanced. The E3 pool
  (BENIGN vs Bot) is separate.
- **Random Forest search:** `max_features` ∈ {sqrt, log2}. 0.3 was dropped for speed. All RF
  rows on all datasets use this space.
- **c8 = c1 exactly.** SMOTETomek balances to exactly 1:1, so recomputed weights are all 1.
  c8 therefore reuses c1's tuned hyperparameters (`params_from` in `common/configs.py`; those
  rows have `n_iter = 0`). Oil Spill and SMS confirmed c8 = c1 to 4 decimals when searched
  independently. This is expected and explained in `RESULTS.md` §4.
- **Threshold-tuning twins** (c3, c5, c6, c7) reuse the tuned hyperparameters of their C = 0
  twin (c0, c1, c2, c4), so the threshold is the only difference. Rows with `n_iter = 0`.
- **E2 NaN thresholds:** at extreme weights a model can score every sample identically, so no
  threshold can be tuned. The default threshold is kept and `threshold` is NaN. 33 rows on Oil
  Spill have this. Intended.
- **E2 uses 1:2 resampling correctly** (the SMOTE ratio is set on the SMOTE object; a test
  covers it). E3 uses 10 search candidates per fold instead of 20, by design.
- Results rows carry several commit IDs (`c5272b8`, `04df632`, `a84542c`, `a4971f8`, `3fb6ef0`,
  `4514c5e`, ...). Between those commits only the documented changes above happened, and each
  affected row was recomputed. This is not a problem.

## 8. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `_ArrayMemoryError`, `MemoryError`, `TerminatedWorkerError`, "worker died" | Out of RAM. Lower `N_JOBS`, close other programs, rerun. Finished rows are kept. |
| First cell: "Package versions differ from requirements.txt" | Wrong environment. Activate `.venv` and `pip install -r requirements.txt`. |
| A notebook "keeps failing" in the runner | Open it: the error is in the saved cell outputs. Fix only if it is a real bug, and commit the fix before rerunning. |
| Machine sleeps or Windows updates restart it | Plug in power, disable sleep while plugged in, rerun the command. Nothing already written is lost. |
| `--status` shows `partial` | Normal after an interruption. Rerun the same `run_experiments.py` command. |
| Many "KeyError ... joblib_memmapping_folder" lines on Windows | Harmless joblib cleanup noise. Ignore it. |
